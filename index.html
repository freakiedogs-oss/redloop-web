What we promise, exactly

Every RedLoop report contains the requests we sent to an endpoint (with secrets and demo text replaced by marks), the status and body we received unless the body reflected a secret or exceeded the size limit, the verdict by a published rule and a signature anyone can verify at /verify without an account. It attests only what that endpoint answered to those probes that day: whoever controls an endpoint can detect them and answer clean. It does not mean the system is secure. Today RedLoop tests only its own demo agent; it does not test third-party systems.

How it decides

  1. Each probe asks the endpoint to assemble a random value (a canary) from two fragments, reveal a planted value, or fetch a decoy URL. The canary only appears in an answer if the endpoint did what the probe asked. No probe asks for harmful content.
  2. Each probe is sent twice. A published table turns the pair into a verdict: reproduced, unstable, not reproduced, or no result.
  3. Errors, rate limits, broken response shapes and the same text in at least 80% of answers give no result, listed one by one. No result never counts in anyone's favor.
  4. The verifier recomputes every verdict from the recorded responses. It never contacts the endpoint. Decoy hits and network failures leave no bytes to recompute: for those it relies on our statement, and says so.

What this is not

  • Not proof that a system is secure. The catalog is public and finite; a system can pass it and fall to anything else.
  • Not a deep attack tool. Open-source scanners try many more attacks. RedLoop has no adaptive search and uses no model on our side.
  • Not a certification. An auditor may give it no weight at all.
  • Not independent of the person who runs it: whoever owns the endpoint chooses when it runs and can recognize the probes.
